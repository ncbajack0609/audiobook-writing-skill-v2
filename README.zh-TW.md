# 繁中有聲書寫作 V2

**把想法與書稿，寫成適合用耳朵理解的繁體中文腳本。**

[English](README.md)

這是一套供 AI 代理使用的寫作 Skill，涵蓋有聲書企劃、紙本改編、單人與雙人配音稿，以及製作交付規格。預設採用**繁體中文、台灣用語與一般成年聽眾**，讓文字稿能交給台灣口音 TTS 工作流或真人製作團隊。

**本 Skill 產出文字，不生成音訊。**

## 適合誰使用

- 想從主題或大綱開始創作有聲書的作者。
- 需要保留原意與內容架構、將現有書稿改編為耳讀腳本的編輯。
- 規劃分集作品、Podbook 或雙人配音內容的創作者。
- 需要一致腳本、讀音表、聲音規格與校聽清單的製作團隊。

核心是「一次聽懂」：每個聽覺單位只承擔一個主要意思，使用自然口語、清楚交代說話者，並把資料來源放在朗讀正文之外。

## 可以完成哪些工作

任務模式可以組合使用；它們與檢查工具的題材選項不同。

| 任務模式 | 準備資料 | 交付內容 |
| --- | --- | --- |
| 新書寫作 | 主題；必要時補充聽眾與篇幅 | 核心問題、目錄與逐章大綱，再進入大量撰稿 |
| 紙本書改編 | 原稿、目標聽眾與聆聽情境 | 全書版／拆分版建議、來源對照、改編風險與耳讀腳本 |
| 全書版／拆分版／Podbook | 原書結構、單集長度或使用情境 | 形式選擇理由、各集命題、原文覆蓋關係與不可遺失內容 |
| 單人／雙人配音稿 | 內容與角色數；角色功能或允許代為設計 | 可朗讀正文、一致角色標示、情緒與停頓提示、讀音風險表 |
| 聲音製作規格 | 定稿腳本、角色或聲音方向 | 聲音人格、角色表、語速與停頓方向、段落切分與後製交付欄位 |
| 校聽檢查準備 | 腳本；實際音檔須另有授權及可用工具 | 文字預檢、七項校聽清單、風險位置與修正建議 |
| 有聲 IP 延伸 | 核心內容、受眾、渠道或目的 | 有聲書、影音課程、金句短影音與 Podbook 的內容映射及文字企劃 |

**Podbook** 以一集一問題、一主題或一故事來組織書籍內容，具有固定節目節奏與可獨立成立的收束。拆分版依內容意義與聽眾需求安排，不按頁數或字數平均硬切。

參考文件另提供六種題材模板：語錄關鍵字拆解、心理故事與諮商對話、職場寓言與人性反轉、AI／社會議題問答論述、雙人對話式有聲書，以及經典作品現代超譯。

## 在 Agent 或 Codex 環境中載入

這個儲存庫是一套 Skill 檔案，不是獨立的有聲書應用程式。請從 [SKILL.md](SKILL.md) 開始；該檔是任務執行的主要依據。

1. 使用代理環境支援的 Skill 載入方式，讓代理能存取**完整目錄**。保留 `SKILL.md`、`references/`、`scripts/` 與 `agents/` 的相對結構。
2. 請代理先讀取 `SKILL.md` 與任務相關參考文件，再開始寫作。若環境不會自動探索 Skill，可明確要求代理讀取所提供目錄中的這些檔案。
3. 提供主題或原稿、目標聽眾、交付形式與限制。改編既有作品時，先確認具有必要權利。

在支援此 Skill 格式的 Codex 環境中，[agents/openai.yaml](agents/openai.yaml) 提供顯示資訊，以及使用 **`$audiobook-writing-v2`** 的預設提示。環境已能載入此 Skill 後，即可在請求中使用這個識別名稱。本儲存庫不含安裝程式；實際載入與探索方式依宿主環境而定。

### 請求範例

**規劃新書**

> 使用 $audiobook-writing-v2，為一般成年聽眾規劃一本談日常決策的繁體中文有聲書。先提出核心問題、目錄與逐章大綱，等我確認後再撰寫章節。

**改編原稿**

> 先讀取 SKILL.md 與改編參考文件。針對我提供的原稿，比較全書版與 Podbook 形式，提出建議、建立各集與來源的對照，並列出不可遺失的內容。

**準備雙人配音交付稿**

> 將提供的章節改成使用繁體中文與台灣用語的 A／B 雙人稿。定義角色功能與聲音人格，附上讀音表、製作規格與校聽清單。不要生成音訊。

新書預設先確認目錄與大綱，再大量撰稿；明確要求一次完成時可連續執行。檢查任務預設交付診斷與可執行建議，需要完整修訂稿時請明確要求改稿。

## 執行文字預檢

在 Skill 目錄中使用 Python 3，並將範例稿件路徑換成自己的檔案：

```sh
python3 scripts/style_check.py path/to/manuscript.md --mode auto
python3 scripts/style_check.py path/to/manuscript.md --mode auto --format json
```

- 輸入格式：`.txt`、`.md`、`.markdown`、`.docx`。
- 題材選項：`auto`、`aphorism`、`counseling`、`workplace`、`social-ai`、`dialogue`、`classic`。
- 報告格式：文字或 JSON；搭配 `--format json` 與 `--output path/to/report.json` 可另存 JSON 報告。
- 檢查內容包含長句、正文網址、未完成標記、來源連結風險、角色標示一致性與讀音風險。自動模式會回報主要題材，以及偵測到的配音形式特徵。
- 結束代碼：`0` 表示規則型檢查通過，`1` 表示需要修訂，`2` 表示輸入或讀取錯誤。

工具使用啟發式規則，不會查證事實或分析音訊。自動評分與編輯審稿規範分開運作；通過分數不代表事實正確、授權完備、朗讀自然或音檔品質合格。

## 與 TTS 的分工

**內容企劃 → 耳讀腳本 → 聲音規格 → 另行授權的 TTS 或錄音 → 實際校聽。**

本 Skill 處理寫作、規格與文字檢查，可以規劃聲音方向、讀音、停頓、段落切分與後製需求，但不執行 TTS、音訊生成、剪輯、混音、影片製作、上架或發布。

這些後續步驟須交由其他工具或製作工作流執行，另行取得明確授權，並確認內容、聲音、音樂與音效的使用權。未知的引擎參數應標示為建議或待實測項目，不虛構設定值。沒有實際音檔與適合工具時，只能交付**校聽前文字檢查**，不能宣稱已完成實際校聽。
